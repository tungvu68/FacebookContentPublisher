- pages_show_list

Nếu tài liệu Meta không truy cập được:

PHẦN 3 — DESKTOP OAUTH THREAT MODEL

Trước khi implement OAuth, tạo:

`docs/META_OAUTH_THREAT_MODEL.md`

Phải phân tích:

- Desktop app là public client, không thể bảo vệ App Secret tuyệt đối.
- App Secret không được embed vào source, executable hoặc PyInstaller.
- Windows Credential Manager giảm rò rỉ ngẫu nhiên nhưng không biến desktop
  executable thành confidential client.
- OAuth callback strategy được Meta hỗ trợ hiện hành:
  - localhost loopback, hoặc
  - custom URI scheme, hoặc
  - HTTPS backend callback.
- State/CSRF validation.
- PKCE nếu Meta flow hiện hành hỗ trợ.
- Authorization code/token leakage.
- Token refresh/expiry/revocation.
- Least-privilege permissions.
- Disconnect và credential deletion.
- App Review và Business Verification.
- Rủi ro malware/process khác trên máy đọc credential.
- Log/diagnostics redaction.

Sau khi kiểm tra tài liệu Meta:

- Nếu desktop public-client flow có thể triển khai an toàn mà không cần
  embedded App Secret, implement flow đó.
- Nếu Meta yêu cầu confidential App Secret cho code exchange:
  - Không embed App Secret.
  - Tạo OAuthBroker interface.
  - Implement MockOAuthBroker.
  - Tạo cấu hình HTTPS backend broker placeholder.
  - Ghi rõ cần backend nhỏ ở Phase 7B.
- Không tự tạo cloud/backend ngoài phạm vi.
- Không dùng browser automation để đăng nhập.
- Không thu thập username/password Facebook.
- Không dùng implicit flow nếu Meta không còn khuyến nghị/hỗ trợ.

PHẦN 4 — FACEBOOK SECRET STORAGE

Mở rộng SecretStore hiện có.

Các credential có thể cần:

- Meta App ID: không nhất thiết là secret, có thể lưu application settings.
- Meta App Secret: chỉ lưu nếu kiến trúc đã xác minh thực sự cần, bằng
  Windows Credential Manager; không embed.
- User access token.
- Page access token theo Page.
- Refresh/long-lived credential nếu Meta cung cấp.
- OAuth state tạm thời không lưu lâu dài.

Quy tắc:

- Service names/key names ổn định.
- Token không nằm trong SQLite.
- SQLite chỉ lưu credential reference/alias và metadata không nhạy cảm.
- Không hiển thị lại token.
- UI chỉ hiển thị Connected/Expired/Revoked/Unknown.
- Delete/Disconnect xóa credential liên quan.
- Không log token trong URL/query/header/body.
- Safe diagnostics phải redact:
  - access_token.
  - appsecret_proof.
  - Authorization.
  - OAuth code.
  - client secret.
- Không fallback sang plaintext.
- Keyring failure phải fail closed.

PHẦN 6 — ERROR MAPPING

Map Graph API/HTTP errors thành application exceptions:

- FacebookNotConfiguredError.
- FacebookAuthenticationError.
- FacebookTokenExpiredError.
- FacebookPermissionError.
- FacebookPageAccessError.
- FacebookRateLimitError.
- FacebookTemporaryError.
- FacebookInvalidContentError.
- FacebookInvalidMediaError.
- FacebookUploadError.
- FacebookTimeoutError.
- FacebookConnectionError.
- FacebookUnknownDeliveryError.
- FacebookProviderError.

Tên có thể theo convention hiện tại.

Phân loại:

Retryable:
- Rate limit khi response cho phép retry.
- Temporary/server error.
- Connection error chắc chắn trước delivery.
- Một số timeout an toàn.

Permanent:
- Invalid/expired token.
- Permission denied.
- Page không có quyền.
- Invalid content.
- Unsupported/invalid media.
- Configuration error.

Ambiguous:
- Timeout/connection loss sau khi request có thể đã tới Meta.
- Scheduler phải chuyển UNKNOWN_RESULT, không auto-retry.

Không dựa chỉ vào HTTP status; parse error envelope theo tài liệu Meta.

PHẦN 7 — OAUTH VÀ CONNECTION SERVICES

Tạo interfaces:

- FacebookOAuthService.
- OAuthBroker nếu cần.
- FacebookConnectionService.
- PageCredentialStore.

Chức năng dự kiến:

- Build authorization URL.
- Sinh cryptographically secure state.
- Lưu state tạm thời với expiry.
- Mở system browser.
- Nhận callback theo strategy đã xác minh.
- Validate exact state.
- Exchange code thông qua flow an toàn.
- Discover permissions.
- Discover Pages.
- Lưu Page credential bằng keyring.
- Test Page access.
- Disconnect.
- Reconnect.
- Detect expired/revoked token.

Yêu cầu:

- Callback listener chỉ bind loopback nếu dùng localhost.
- Random high port nếu flow cho phép.
- Timeout callback.
- Không chấp nhận callback không đúng state.
- Không hiển thị token trong browser response.
- Có success/failure HTML tối thiểu nếu dùng loopback.
- Đóng listener sau completion/timeout.
- Không block Qt UI.
- User có thể cancel.
- Không tự mở nhiều login flow đồng thời.
- Không gọi live OAuth trong automated tests.

Nếu chưa thể xác minh Meta hỗ trợ loopback/custom scheme:

- Implement interface và mock callback flow.
- Disable Connect trong production với lý do rõ.
- Không implement flow giả có vẻ hoạt động.
